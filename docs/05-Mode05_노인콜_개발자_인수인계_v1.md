## 1. 문서 목적·대상·범위·비범위·기준일

### 1.1 목적

Mode 05만 필요한 개발자가 **로컬에서 인·아웃바운드 전화를 재현**하고, 이후 **노인콜 제품(안부 프롬프트·세션 로깅·위기 핸드오프·대시보드)** 으로 옮길 때 빠뜨리지 않도록 정리한다.

### 1.2 범위 (이 문서가 다루는 것)

- **Mode 05**: ClawOps = **전화 레이어만**(070/SIP). 상담 AI = **퐁 쪽** LiveKit Agent 워커(STT-LLM-TTS 또는 OpenAI Realtime).
- 실험실 코드: `voiceTEST` (Mode 05 앱·API) + `SeniorCall/TestAgent` (Room 안 `agent.py`).
- 공적 맥락: 노인맞춤돌봄서비스 안에서의 **안부확인·안전지원·위기 에스컬레이션 접점** (조사보고서 요지).

### 1.3 비범위 (한 줄)

- 행복e음·노인맞춤돌봄시스템 **공식 실적 양방향 연동**, 자동 119 출동 → 제품 Later / 정책 미확정.
- ClawOps VoiceML `<Connect><Stream>` 브리지(아웃바운드 플랜 B) → 본 문서에서는 **폴백 후보만** 언급, 구현 명세 없음.

### 1.4 라벨 정의

| 라벨 | 의미 |
|------|------|
| **【확정】** | 원자료(가이드·코드·ClawOps 회신 정리·PR)에서 확인 |
| **【가설】** | 합리적 추론·제품 PRD 가정. 구현 전 검증 필요 |
| **【미확인】** | 근거 부족 또는 문서 간 불일치 |
| **【외부주장】** | ClawOps·공시 요금·보도 등 외부 출처. 계약서·최신 공시와 재확인 |

## 2. 한 장 요약

### 2.1 아키텍처 (한 문단)

**【확정】** 어르신 전화망(PSTN)은 **ClawOps 070 + SIP 트렁크**를 거쳐 **LiveKit Cloud SIP**로 들어가고, 통화는 **LiveKit Room**의 참가자가 된다. 같은 Room에 로컬(또는 배포된) **Agent 워커**(`agent.py`, 예: OpenAI Realtime 안부)가 붙어 STT-LLM-TTS/Realtime을 수행한다. `voiceTEST` Mode 05 앱은 헬스·체크리스트·모니터 토큰·아웃바운드 **Agent Dispatch + CreateSIPParticipant**를 도우며, **대화 엔진 자체를 대체하지 않는다**.

### 2.2 핵심 결정 (7)

1. **전화 레이어만 ClawOps, AI는 퐁 유지** — ClawOps 매니지드 Agent는 Mode 05에서 쓰지 않음.【확정】
2. **인바운드**: 070 → ClawOps SIP 엔드포인트+라우트(TLS) → LiveKit Inbound trunk → Dispatch → 워커.【확정】(ClawOps 측 “운영 환경 실통화” 회신 + Mode 05 가이드)
3. **아웃바운드(랩 경로)**: 앱/다이얼이 **먼저 Agent Dispatch**, 이어서 **CreateSIPParticipant**(Outbound trunk **TLS**). 워커가 metadata에 `phone_number`를 들고 dial하는 경로(`dial.py`)도 있음.【확정=코드·가이드】 / ClawOps 공식 “LiveKit 짝 검증”은 세션 시점 **미검증**이었음 → **현재 운영급 검증 여부는【미확인】** (아래 §10).
4. **Softphone ‘SIP 단말’ 경로 금지** — Mode 05는 **SIP 엔드포인트 + SIP 라우트**.【확정】
5. **070 인바운드 라우팅**: ClawOps에서 **SIP 엔드포인트 + SIP 라우트**를 사용해야 한다. 테스트 시 해당 SIP 라우팅을 활성화한다.【확정】
6. **`LIVEKIT_AGENT_NAME` + 워커 기동 필수** — 없으면 벨만 울리고 Room이 비어 무음.【확정】(PR #4)
7. **번호 포맷**: `070…` / `010…` 또는 `+82…`. **`+070` / `+010` 금지**.【확정】

### 3.2 전화 AI가 끼는 지점 (노인콜)

**【확정=PRD】** 앱 없이 전화만으로 안부·말벗·간단 스크리닝 → 이상·미접촉·요청 시 **생활지원사·센터 큐** → 운영 콘솔에서 조치.

## 5. 시스템 아키텍처

### 5.1 컴포넌트

```
[어르신 휴대폰/유선]
        ↕ PSTN
[ClawOps]  070 번호 · SIP 트렁크 · (인)엔드포인트+라우트 / (아웃)digest SIP 도메인
        ↕ SIP TLS :5061
[LiveKit Cloud SIP]
  · Inbound trunk (numbers, allowedAddresses)
  · Outbound trunk (address=호스트만, TLS, auth)
  · Dispatch rule (roomPrefix, agentName)
        ↕
[LiveKit Room]  ← SIP 참가자 + Agent 워커
        ↕
[Agent 워커]  SeniorCall/TestAgent/agent.py  (OpenAI Realtime 등)
        ↕ (제어만)
[voiceTEST Mode 05]  health · monitor token · outbound dispatch+SIP
```

| 컴포넌트 | 역할 | 라벨 |
|----------|------|------|
| **070 번호** | 인·아웃 발신표시/착신. 예(문서): `07052767794` (하이픈 없이 env) | 【확정=가이드 예시】 |
| **ClawOps SIP 트렁크** | PSTN↔SIP. phone-layer-only | 【확정】 |
| **SIP 엔드포인트+라우트** | 인바운드 070 → `sip:<sub>.sip.livekit.cloud:5061` TLS | 【확정】 |
| **LiveKit Inbound/Outbound trunk** | INVITE 입·출구 | 【확정】 |
| **Dispatch rule / Agent Dispatch** | 인바운드 자동 / 아웃바운드 앱·API | 【확정】 |
| **Agent 워커** | 상담 AI. `LIVEKIT_AGENT_NAME` (기본 `phone-test-openai`) | 【확정】 |
| **STT-LLM-TTS / Realtime** | 현재 TestAgent는 **OpenAI Realtime**【확정】. 파이프라인 교체는 워커만 교체【확정=가이드 §8】 |
| **voiceTEST** | 랩 UI·API. 워커를 대신 띄우지 **않음** | 【확정】 |

### 5.2 인바운드 시퀀스 (단계)

1. 어르신 → **070** 발신.【확정】
2. ClawOps: 번호 인바운드 라우팅 = **SIP** → 활성 엔드포인트 → LiveKit URI (TLS).【확정】
3. LiveKit Inbound trunk: `numbers`·`allowedAddresses`(시그널링 IP) 매칭.【확정】
4. Dispatch rule: `call-…` Room 생성 + `agents[].agentName` Job.【확정】
5. 로컬 `python agent.py dev` 워커가 Room 참가 → SIP 참가자 대기 → Realtime 세션·첫 인사.【확정=코드】

### 5.3 아웃바운드 시퀀스 (단계) — Mode 05 앱 경로

1. `voiceTEST`가 Room 이름 생성 (`LIVEKIT_ROOM_PREFIX` + uuid).【확정】
2. **Agent Dispatch** (`agent_name`, metadata `{}`).【확정=PR #4】
3. 워커가 inbound처럼 SIP 참가자 대기.【확정】
4. **CreateSIPParticipant** (Outbound trunk TLS, `sip_call_to`, 선택 `sip_number`=From).【확정】
5. ClawOps → PSTN → 어르신 벨 → 수화 후 같은 Room에서 대화.【확정=가이드】 / 운영 검증【미확인】

### 5.4 아웃바운드 — `dial.py` / metadata 경로 (대안)

1. Dispatch metadata `{"phone_number":"010…"}`.【확정=TestAgent】
2. 워커가 스스로 `CreateSIPParticipant` (`wait_until_answered=True`).【확정】
3. voiceTEST 앱 경로와 **누가 dial하느냐**만 다름. Room에서 만난다는 구조는 동일.【확정】

### 5.5 가격 참고 (구현과 무관, 견적용)

**【외부주장】** ClawOps 공시(세션 정리 2026-09-17): Business ₩99,000/월 + SIP 트렁크 ₩99,000/월; 동시통화 상향 ₩100,000→100; 초과 발신 ₩60/분 · 수신 ₩4/분; 번호 ₩1,000/개. AI 부가 불필요(자체 AI). **계약·최신 공시와 재확인.**

### 7.3 ClawOps 설정 체크리스트

- [ ] SIP 트렁크 부가 ON
- [ ] **SIP 엔드포인트**(❌ SIP 단말 아님) + LiveKit URI · **TLS** · 활성
- [ ] SIP 라우트 ≥ 1 · 활성 (`routingType=sip` 전제)
- [ ] 070 인바운드 = **SIP** (해당 엔드포인트)
- [ ] (아웃) digest 도메인·user·password 확보 → LiveKit Outbound trunk에 반영
- [ ] 070 인바운드 라우팅 대상이 SIP 엔드포인트인지 확인

### 7.4 LiveKit 설정 체크리스트

- [ ] Inbound trunk: `numbers`가 ClawOps Request-URI와 **완전 일치** (`070…` 먼저, 안 되면 `+82…`, ❌ `+070…`)
- [ ] `allowedAddresses`: 시그널링 `34.47.65.45` (프로젝트 IP allowlist enable 필요할 수 있음)
- [ ] Dispatch rule: `roomPrefix` + `agentName` = 워커명
- [ ] Outbound trunk: `address` = **호스트만** (sip:/:5061 넣지 않음), **TLS**, `numbers`=070, digest auth
- [ ] 콜 상세에서 **Signaling Connection Type = TLS** 확인

> JSON에 `"transport": "SIP_TRANSPORT_TLS"` 넣으면 생성 실패할 수 있음 → transport 없이 생성 후 UI에서 TLS, 또는 `"transport": "TLS"` 시도.【확정=가이드】

### 7.7 실패 시 알려진 이슈

| 증상 | 원인 후보 | 상태 |
|------|-----------|------|
| 인바운드에 SIP 옵션 없음 | 엔드포인트/라우트 미활성, **SIP 단말만** 설정 | 【확정=해결책 문서화】 |
| LiveKit “trunk 없음” | `numbers` 형식 (`070` vs `+82`) | 【확정】 |
| 아웃바운드 timed out / **벨 안 울림** | Signaling **UDP**(→TLS), 또는 `+070`/`+010` | 【확정】 |
| 벨은 울리는데 **무음·무응답** | 워커 미기동, `agentName` 불일치, **Agent Dispatch 누락** | 【확정=PR #4로 앱 경로 수정】 |
| 070 인바운드 실패 | SIP 엔드포인트·라우트 미활성 또는 라우팅 대상 오류 | 【확정】 |
| JSON transport 필드 생성 실패 | `SIP_TRANSPORT_TLS` 문자열 이슈 | 【확정=가이드】 |
| CreateSIPParticipant↔ClawOps **운영 안정성** | 세션 시점 미검증 | 【미확인】 — 랩에서 가이드대로면 통화 가능했다는 서술과 **불일치 가능**. 재현 로그로 확정할 것 |
| 코덱(PCMU/PCMA)·SRTP | 회신에 명시 없음 | 【미확인】 |
| LiveKit Cloud **발신 IP 고정** 여부 (ClawOps IP allow) | 세션 액션 항목 | 【미확인】 |
